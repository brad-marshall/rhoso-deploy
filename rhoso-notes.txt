Networks required:

Only ctlplane and internalapi are required networks

storage is only required if glance or cinder need direct access to ceph or SAN
tenant is compute to compute only
- needed on OCP if you host OVN gateway routers as pods on the OpenShift cluster


-----------------------------
Interfaces on control plane need to have certain settings:

# MAC address spoofing
Get-VMNetworkAdapter -VMName "OCP-ControlNode*" | Set-VMNetworkAdapter -MacAddressSpoofing On

# VLAN Trunking
# Set adapter to Trunk mode, passing tagged VLANs to the VM
Get-VMNetworkAdapter -VMName "OCP-ControlNode*" | Set-VMNetworkAdapterVlan -Trunk -AllowedVlanIdList "1-4094" -NativeVlanId 0

# Disable Dynamic memory, can cause etcd crashing
Set-VMMemory -VMName "OCP-ControlNode*" -DynamicMemoryEnabled $false

# If VMs are Gen2, disable Secure boot or witch to MS UEFI cert auth
Set-VMFirmware -VMName "OCP-ControlNode*" -EnableSecureBoot On -SecureBootTemplate "MicrosoftUEFICertificateAuthority"

# Create a SET-enabled External Virtual Switch on Windows Server
New-VMSwitch -Name "RHOSO-vSwitch" -NetAdapterName "NIC1","NIC2" -EnableEmbeddedTeaming $true

Network Config:

```
---
# Example NodeNetworkConfigurationPolicy (NNCP) snippet for VLAN 20 (internalapi)
# Need another one of these for vlan 10 (ctlplane) if you are using it tagged
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: internalapi-vlan
spec:
  desiredState:
    interfaces:
      - name: eth0.20
        type: vlan
        state: up
        vlan:
          base-iface: eth0
          id: 20
---
# Example NetworkAttachmentDefinition for internalapi
apiVersion: [k8s.cni.cncf.io/v1](http://k8s.cni.cncf.io/v1)
kind: NetworkAttachmentDefinition
metadata:
  name: internalapi
  namespace: openstack
spec:
  config: |
    {
      "cniVersion": "0.3.1",
      "name": "internalapi",
      "type": "macvlan",
      "master": "eth0.20",
      "mode": "bridge"
    }
---
# Define the actual networks
apiVersion: network.openstack.org/v1beta1
kind: NetConfig
metadata:
  name: openstacknetconfig
  namespace: openstack
spec:
  networks:
    # 1. Control Plane Network (Management / Provisioning / Ansible SSH)
    - name: ctlplane
      vlan: 10
      dnsDomain: ctlplane.example.com
      subnets:
        - name: subnet1
          cidr: 172.22.0.0/24
          gateway: 172.22.0.1
          allocationRanges:
            - start: 172.22.0.100
              end: 172.22.0.150

    # 2. Internal API Network (OpenStack RPC, Database, & Controller Traffic)
    - name: InternalApi
      vlan: 20
      dnsDomain: internalapi.example.com
      subnets:
        - name: subnet1
          cidr: 172.17.0.0/24
          allocationRanges:
            - start: 172.17.0.100
              end: 172.17.0.150

#### DON'T NECESSARILY NEED THESE ####
    # 3. Storage Network (Glance image transfers, Ceph / Cinder access)
    - name: Storage
      vlan: 30
      dnsDomain: storage.example.com
      subnets:
        - name: subnet1
          cidr: 172.18.0.0/24
          allocationRanges:
            - start: 172.18.0.100
              end: 172.18.0.150

    # 4. Tenant Overlay Network (Geneve / VXLAN encapsulation traffic)
    - name: Tenant
      vlan: 40
      dnsDomain: tenant.example.com
      subnets:
        - name: subnet1
          cidr: 172.19.0.0/24
          allocationRanges:
            - start: 172.19.0.100
              end: 172.19.0.150
```

-----------------------------
Glance:

Add extra disk to all 3 control plane nodes
Using LVM Storage Operator, create a local storage class - usually topolvm-system
Use the follwing in the glance config:
```
spec:
  glance:
    enabled: true
    template:
      storage:
        storageRequest: 50Gi
        storageClass: topolvm-system
```

Compute node

Instances:
Instances stored in /var/lib/nova/instances
- mount a large volume into /var/lib/nova

Cinder:
Create a raw disk or partition and make a LVM VG called cinder-volumes
pvcreate /dev/sdb
vgcreate cinder-volumes /dev/sdb

# Openstack DataPlane Node Set
apiVersion: dataplane.openstack.org/v1beta1
kind: OpenStackDataPlaneNodeSet
metadata:
  name: openstack-compute-nodes
  namespace: openstack
spec:
  # Instructs RHOSO that RHEL is already installed on the physical host
  preProvisioned: true

  # Connects the node set to the OCP ctlplane network
  networkAttachments:
    - ctlplane

  # The Ansible services RHOSO will configure on the physical compute node
  services:
    - download-cache
    - configure-network
    - validate-network
    - install-os
    - configure-os
    - run-os
    - ovn
    - neutron-metadata
    - nova

  nodeTemplate:
    managementNetwork: ctlplane
    
    # Secret in OpenShift containing the SSH key to log into your physical host
    ansibleSSHPrivateKeySecret: dataplane-ansible-ssh-private-key-secret
    
    ansible:
      ansibleUser: cloud-admin
      ansiblePort: 22
      ansibleVars:
        timesync_ntp_servers:
          - hostname: pool.ntp.org

  # Individual physical node definitions
  nodes:
    compute-0:
      ansibleHost: 172.22.0.50  # Physical host IP on the ctlplane network
      hostName: compute-0.ctlplane.example.com
---
# Actual deployment of host
apiVersion: dataplane.openstack.org/v1beta1
kind: OpenStackDataPlaneDeployment
metadata:
  name: openstack-compute-deploy
  namespace: openstack
spec:
  nodeSets:
    - openstack-compute-nodes
---
Network configuration for RHEL Compute Node

Needs RHEL 9.4+ installed and can ssh into the ctlplane node with the ssh key in OpenShift
- OpenStackDataPlaneNodeSet nodeTemplate.ansibleSSHPrivateKeySecret
Static IPs in ctlplane and internalapi - and tenant if you are using it
Use these within the edpm_network_config_template variable within your OpenStackDataPlaneNodeSet
```
# Untagged ctlplane example
network_config:
  - type: ovs_bridge
    name: br-ex
    use_dhcp: false
    addresses:
      - ip_netmask: 172.22.0.50/24  # ctlplane IP directly on base bridge
    routes:
      - default: true
        next_hop: 172.22.0.1
    members:
      - type: interface
        name: ens3f0              # Your single physical NIC
        primary: true
  - type: vlan
    device: br-ex
    vlan_id: 20                   # internalapi VLAN
    addresses:
      - ip_netmask: 172.17.0.50/24
  - type: vlan
    device: br-ex
    vlan_id: 40                   # tenant VLAN
    addresses:
      - ip_netmask: 172.19.0.50/24

# Tagged ctlplane example
network_config:
  - type: ovs_bridge
    name: br-ex
    use_dhcp: false
    members:
      - type: interface
        name: ens3f0              # Your single physical NIC
        primary: true
  - type: vlan
    device: br-ex
    vlan_id: 10                   # ctlplane tagged on VLAN 10
    addresses:
      - ip_netmask: 172.22.0.50/24
    routes:
      - default: true
        next_hop: 172.22.0.1
  - type: vlan
    device: br-ex
    vlan_id: 20                   # internalapi VLAN
    addresses:
      - ip_netmask: 172.17.0.50/24

```
